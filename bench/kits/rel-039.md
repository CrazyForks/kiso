# rel-039 ceremony — the ready kit

**Frozen 2026-09-17, BEFORE any leg runs.** Nothing below is tuned to the
round it judges.

## The arms

| | |
|---|---|
| rc | **0.39.0**, packed from main after #48 and #49 merge, clean prefix |
| ctl | **0.38.0**, the PUBLISHED release, separate clean prefix |
| invocation | absolute path, both arms |
| per-leg gate | each leg verifies the version it ACTUALLY ran |

That last line has caught its class **three times**: `npx -y pkg@version`
resolving through a local `node_modules` link so the control leg ran the
candidate under the ctl label, and twice an unbumped tree where both arms
reported the same version — a ceremony that compares a build against
itself and reports perfect agreement.

## Design

12 interleaved rc/ctl pairs, T5, 24 legs, on the SAME endpoint as every
previous round (DeepSeek direct, `deepseek-flash`). The Command Code
gateway was verified usable today — caching passes through, 56% on a
short prompt — but it serves a different model id, so a round there is
not comparable to the historical numbers. The owner chose comparability.

Interleaved rather than batched: the pairing is what cancels common-mode
provider drift, which is also why the legs are not parallelised for
speed.

## Criteria — `bm1-a1`, read from `paired-compare.mjs`

| | |
|---|---|
| verify | **100%** |
| median(d_cost), cost-weighted | **≤ +20%** |
| median(d_wall) | **≤ +25%** |
| a single pair > +50% | an **ANOMALY NOTE**, never a block |

## Causal relevance — why this round is paid at all

BM-1 §3: a renderer round's paired bench is INFORMATIONAL; a
prompt/tool-schema round's BLOCKS. This round mixes both — ACI-6 is a
prompt change, the grid and the three TUI items are renderer — and **a
mixed round takes the strictest tier.**

So the cost gate is ACI-6's. It is a pure DELETION (−191 bytes, ~48
tokens off every request), and the measured history that makes prompt
rounds block — PR-1c's +35%, traced to reasoning tokens — was about ADDED
text. The expectation is therefore no movement; the gate exists because
that expectation has been wrong before.

The renderer half blocks on its own gates instead: PTY and visual, which
`npm run check` already carries.

## What a failure means

Out of band on the EXPENSIVE side, or any failed verify: blocker-class, a
hard stop before the release, awaiting adjudication. Out on the CHEAP
side with every leg verify=pass is improvement-class and ships carrying
"proposed, for the reviewer" (the S1-1 directional clause).

## What this round cannot say

n=12. Per-pair spread near 30 points; it cannot resolve an effect under
about 20%, and two ceremonies of the same change once disagreed by 22
points. **The verdict is a REGRESSION GATE, not a measurement of
improvement.** No cost number from it will be claimed as a win.

## A VOID is not a FAIL

rel-038 lost a leg to a provider connection error — the model never
answered. The per-leg void check compares only the VERSION, so it read
"0 void" for a leg that produced nothing. **This round's runner also
greps each leg's stdout for `Connection error`**, and a leg whose model
never answered is void, not failed: it is evidence about nothing.

Re-running such a pair is legitimate because the trigger is that the
OBSERVATION does not exist — checkable without looking at what it cost.
Re-running because a delta is unwelcome is not, and the criteria above
are not touched either way.
