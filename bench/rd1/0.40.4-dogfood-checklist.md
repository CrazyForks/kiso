# 0.40.4 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.40.4 is APPROVED. This release changes one surface: how a
profile reaches a gateway that needs a session header.

```
npm install -g @vincemakes/kiso-code@0.40.4
kiso --version        # 0.40.4
```

## A. The gateway profiles, direct

The agent switches the gateway profiles to the direct form after the
publish (the config is backed up first): `baseUrl` is the gateway's own
URL and `headers` names its session header with `{session}`.

1. Quit every running kiso and start a new one on a gateway profile. Run
   `/model`.
   - **Expected:** the gateway profiles read `@<gateway host>`, with no
     `via 127.0.0.1:47821`.
2. Work as usual for a while.
   - **Expected:** replies arrive as before; the recap's cache figure is
     as high as it was through the forwarder.
3. `/resume` an earlier session on a gateway profile and send one turn.
   - **Expected:** it answers.
4. The forwarder is no longer needed. With the migration the agent also
   removes the one line in `kiso-op-bypass` and `kiso-co-bypass` that
   started it (`kiso-op-go-shim ensure`; both scripts backed up first).
   The running forwarder is left alone until no gateway session is open;
   then `kiso-op-go-shim stop` ends it for good.
