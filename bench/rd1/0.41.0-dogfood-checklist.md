# 0.41.0 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.41.0 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.41.0
kiso --version        # 0.41.0
```

A session opened before the install runs the old kiso — it says so after
its next turn. Exit it and resume it (`kiso resume <id>`).

## A. Nothing changed for kiso-code — and that is the check

0.41.0 changes no prompt byte and no tool of the coding agent (the tool
table is pinned byte-for-byte against the pre-release capture). A normal
session — read, edit, shell, a `/compact` — behaves as 0.40.7 did.

1. Start plain `kiso` on any project, ask for a small change, let it edit
   and run the tests.
   - **Expected:** the same shape of turns as 0.40.7; the tool table
     lines in `/context` (base prompt, tool table, messages) carry the
     same figures as before for the same project.
2. `/status` ends with `version 0.41.0`.

## B. The three new packages (only if you want to look)

They are not on kiso-code's path. If you want to see them exist:

```
npm view @vincemakes/kiso-server version      # 0.41.0
npm view @vincemakes/kiso-protocol version    # 0.41.0
npm view @vincemakes/kiso-client version      # 0.41.0
```

The products adopt them next (kiso-doc
the host-adoption brief in kiso-doc); nothing in this release
asks you to.

## C. What would be a finding

- Any `never shell cat/head/tail`-style line MISSING from the coding
  agent's `Tool use:` block — the rows should be exactly as before.
- A session that behaves differently from 0.40.7 on the same task.
