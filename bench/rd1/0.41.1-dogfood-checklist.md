# 0.41.1 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.41.1 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.41.1
kiso --version        # 0.41.1
```

A session opened before the install runs the old kiso — it says so after
its next turn. Exit it and resume it (`kiso resume <id>`).

## A. Nothing changed for kiso-code — and that is the check

0.41.1 touches `packages/server` and two doc sentences; kiso-code imports
none of it. A normal session behaves as 0.41.0 did; `/status` ends with
`version 0.41.1`.

## B. The service (only if you want to look)

`npm view @vincemakes/kiso-server version` → 0.41.1. What changed for a
host: a factory bound to a different store is now refused at the first
run's settle (`StoreMismatchError`); `close()` does not close the store;
nested tool arguments are sanitized on the wire.

## C. What would be a finding

- A session that behaves differently from 0.41.0 on the same task.
