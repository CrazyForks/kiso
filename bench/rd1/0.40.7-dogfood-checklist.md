# 0.40.7 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.40.7 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.40.7
kiso --version        # 0.40.7
```

A session opened before the install runs the old kiso — it says so after
its next turn. Exit it and resume it (`kiso resume <id>`).

## A. `/model` and `/mode`

1. Start plain `kiso` (your default profile), then `/model`.
   - **Expected:** the highlight is ON your current profile, not the first
     row; press Enter — the session stays where it was.
   - The typed list (`/model` in a pipe, or the rows' notes) says
     `stored key` for the profiles your stored keys pay, not an env var
     name.
2. `/model`, move to a profile on another endpoint (e.g. `co`), Enter.
   - **Expected:** under `model → co (…)`, one more line:
     `paid by @api.commandcode.ai · stored key from the next turn — was
     @api.deepseek.com · stored key`.
3. `/mode` — the highlight is on the tier in force (`bypass` for you).

## B. The ChatGPT profiles

1. `/model` — the `chatgpt` / `sol` rows.
   - **Expected:** `oauth, expired — renews on use` if the sign-in's token
     is past its expiry but renewable; `(unavailable)` naming
     `kiso login chatgpt` if the renewal was refused. `kiso auth` says the
     same.

## C. Nothing to see (and that is the check)

- A gateway that drops its upstream mid-answer now retries instead of
  stopping the run — you will only notice it by NOT having to type
  "continue".
- After a `kill -9`'d session, the next `kiso` start removes the leftover
  `kiso-mcp-*` / `kiso-skills-*` directories from your temp directory.
