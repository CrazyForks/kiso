# 0.40.3 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both sessions go
into the record before 0.40.3 is APPROVED. This list is what the owner's
pass should look at: the surfaces this release changed.

Install the published build first:

```
npm install -g @vincemakes/kiso-code@0.40.3
kiso --version        # 0.40.3
```

## A. The window follows the model (CW-1)

1. Optional first: in `~/.kiso/config.json`, add `"upstream"` to each
   profile whose `baseUrl` is the local forwarder, naming where it
   forwards (the gateway's URL). Remove the `"contextWindow": 1048576`
   added for 0.40.2 from those profiles to see the new chain answer on
   its own (keep it if you prefer your own figure; yours always wins).
2. Start kiso on the forwarder profile and run `/status`.
   - **Expected:** `ctx ~N% · window 1M, inferred from the model
     (deepseek-flash) — not stated for this endpoint`, and the model line
     reads `@<gateway> via 127.0.0.1:47821`.
   - **The old defect looked like:** `ctx ?` on the status row, and no
     window named anywhere.
3. `/model` (the panel or the typed list): each row ends with its window —
   `ctx 1M`, `ctx 1M inferred`, `ctx <your figure>`, or `ctx ?` for a model
   nobody states.
4. If an endpoint ever refuses a long context, one line says so:
   `✦ window learned — <host> refused <model> past N tokens; compaction
   now aims below it`, and `/status` then says `learned from this
   endpoint's refusal (<date>)`. The figure is kept in
   `~/.kiso/learned-windows.json`.

## B. The first turn no longer reports a miss (usage counted once)

1. Start a fresh session on the forwarder profile and send one short
   message.
   - **Expected:** the recap shows `fresh` with no `miss` on the first turn.
   - **The old defect looked like:** `fresh 3k · miss 3k` on a first turn.

## C. `edit_file` retries (ACI-3)

1. Work normally for a while with edits. When an edit fails, read the
   result the model got (ctrl+o on the tool card):
   - a missing pattern shows the file's text around where the search
     should land and ends on `[rev …]`;
   - a stale revision shows where each hunk stands in the file as it is;
   - several hunks in one edit apply in order.
   - **Expected:** fewer read-then-retry cycles after a failed edit.

## D. No more empty sessions (DC-60)

1. Start kiso and quit before typing anything (`exit`). Open `/resume` in
   a new session.
   - **Expected:** no new "no summary" entry for the session you quit.
2. The 56 left by earlier versions:
   ```
   kiso sessions --prune-empty          # lists them
   kiso sessions --prune-empty --yes    # moves them to the Trash
   ```
   - **Expected:** a list, then a move into ONE new folder in the Trash;
     nothing deleted; a session held by a running kiso is skipped and
     counted.
