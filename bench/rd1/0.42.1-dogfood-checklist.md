# 0.42.1 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.42.1 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.42.1
kiso --version        # 0.42.1
```

## A. Nothing changed for kiso-code — and that is the check

0.42.1 changes how an EMPTY base prompt and an UNDEFINED function append
compose (no bare separator). kiso-code has a non-empty base prompt and
string appends, and its request bytes are pinned unchanged by the byte
fixture. A normal session behaves as 0.42.0 did; `/status` ends with
`version 0.42.1`.

## B. What would be a finding

- A session that behaves differently from 0.42.0 on the same task.
- A drop in the cache ratio within one turn (the prompt prefix moved).
