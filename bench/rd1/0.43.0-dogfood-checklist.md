# 0.43.0 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.43.0 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.43.0
kiso --version        # 0.43.0
```

## A. A normal session, and one detail to watch

0.43.0 replays a tool call's arguments as the model's own text on later
requests (the one change the model can see). A multi-step edit task
with a test run should behave as 0.42.3 did; `/status` ends with
`version 0.43.0`. Watch `cache` on the status line across the turns of
one session: it should stay high after the first turn, as before.

## B. An old session, continued

Resume a session created on 0.42.x and continue it with one more turn.
That turn replays the old calls' raw text for the first time: expect a
one-time drop in the cache ratio on that turn only, and normal behaviour
after it.

## C. What would be a finding

- A session that behaves differently from 0.42.3 on the same task
  (more tool calls for the same edit, a different diff).
- A cache ratio that stays low after the first turn of a session.
- A run that ends, or fails to end, differently after a crash resume.
