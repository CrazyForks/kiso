# 0.43.0 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.43.0 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.43.0
kiso --version        # 0.43.0
```

## A. A normal session — nothing the coding agent sends changed

The raw-text replay that the first 0.43.0 candidate carried was withdrawn
before the release (finding 0430-B1): the coding agent's request bytes
are as in 0.42.3. A multi-step edit task with a test run should behave
as 0.42.3 did; `/status` ends with `version 0.43.0`; `cache` on the
status line stays high after the first turn, as before.

## B. A crash resume, if you want to look

Interrupt a session mid-tool (kill the process) and resume it: the
recovered execution behaves as the fresh one would, and the session's
log carries no extra decision event for it (0430-F1).

## C. What would be a finding

- A session that behaves differently from 0.42.3 on the same task
  (more tool calls for the same edit, a different diff).
- A cache ratio that stays low after the first turn of a session.
- A run that ends, or fails to end, differently after a crash resume.
