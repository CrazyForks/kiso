# 0.40.1 — dogfood checklist (for the owner's manual pass)

Install: the local 0.40.1 build is installed globally (`kiso --version` → `0.40.1`,
`which kiso` → the nvm bin). Nothing was published.
Rollback: `npm install -g @vincemakes/kiso-code@0.40.0`.

Everything below is what CHANGED. Anything not on this list should feel exactly
as it did in 0.40.0.

## A. resume semantics (findings DC-55, DC-8's leftovers; the 2026-09-21 ruling)

The refusal you hit — `the recorded execution profile no longer matches this
process` — must be gone from every path.

1. **A session recorded on another provider opens.** Start with the wrapper you
   use (`kiso-co-bypass`, so the binding is `custom` / your commandcode
   endpoint), then `/resume <an old session recorded on the other provider>`.
   Expected: it opens, prints one line `binding changed — now on <model>: the
   recorded provider is … ; reasoning reset to defaults`, and the next turn runs
   under the CURRENT configuration. No refusal, and the REPL stays alive.
2. **`--accept-drift` is inert.** Passing it changes nothing (kept only so old
   scripts do not break).
3. **A model switch inside one provider opens too** (the same ruling, taken on
   review): record a session on model A, start with model B of the same
   provider, `/resume` — the session runs B, records revision N+1, and says so.
4. **Integrity is still fail-closed.** A session whose sidecar cannot be read,
   or an XP-era session with scoped envelopes and no sidecar, is still refused.
   Two things to check while you are there: an in-session `/resume` to such a
   session prints the message and does NOT kill the REPL (this was the bug that
   left the three ghost sessions), and `kiso resume <that id>` at the ENTRY
   still fails loudly with a non-zero exit.
5. **A line pasted with a refused switch is never answered by the old session.**
   Paste `/resume <blocked id>` and a prompt on ONE line-pair (or pipe both
   lines). Expected: the refusal, then `[1 line held back — the switch was
   refused, so nothing was run]` plus the line itself. The prompt must NOT
   appear in the old session's log. A target that does not exist at all (a
   typo, or a session that cannot be listed) is different: the refusal is
   `no such session`, and the prompt stays where you are — on purpose.
6. **Thresholds follow the LIVE model.** A session recorded on a 1M model,
   resumed while your process serves a 200k model, now compacts at the 200k
   window (before, it kept the recorded 1M window). This is the ruling's
   consequence, not a regression — but it is the one place where the change is
   visible as "kiso compacts earlier than it used to".

## B. ask / approval panel and the scrollback (finding DC-56)

7. With an ask or approval panel up, the already-streamed output can be
   scrolled: your terminal's own wheel / PageUp must work while the question is
   on screen. Nothing should eat the mouse.
8. After the panel closes, everything is as before (no mouse mode left on, no
   escape residue, `exit`/handover paths included).

## C. /model panel: reach, provider, current mark (finding DC-58 + the review)

9. `/model` on a config with more than nine profiles: ↑↓ walk ALL of them; the
   block shows `↕ A-B / N — ↑↓ scrolls` when the list does not fit.
10. A **digit names the row on screen** — scroll first, then press `1`: the
    selection is the first VISIBLE row, not the first row of the list.
11. **The provider is on every row** (`openai-compat/deepseek-v4-flash
    @commandcode.ai`). Two profiles on the same model id but different accounts
    must read differently.
12. The `current` mark lands only on the profile actually running, and when it
    cannot be known it marks NOTHING (it never guesses from a model name and a
    host — two profiles can share both and differ only by API key env).
13. **Small terminal** (≈8-10 rows): the pick panel still draws fewer rows than
    nine, and the digits still name the rows you can see.
14. The switch notice names the account (`model → ds (deepseek-v4-flash
    @api.deepseek.com) — takes effect on the next turn`), and `/status` carries
    `model <id>@<host> · profile <name>`.

## D. Regression feel (unchanged surfaces)

15. A normal session end to end: tools, approvals, `/compact`, `/clear`,
    resize, ctrl+o/c, `esc`.
16. `/model` and `/resume` in the interactive loop, plus `kiso -p`,
    `kiso resume <id> <text>`, `kiso chat <id>` (the three entry points).
17. `kiso-co-bypass`, your extensions, MCP servers and skills still load.

## Notes for whoever runs the test suite locally

- `npx vitest run -c vitest.pty.config.ts` (169 PTY files, ~21 min) must be run
  with a clean environment: a stray `KISO_DELEGATION_CONFIG_JSON` in the shell
  points the child processes at your REAL sessions dir and makes six subagent
  cases fail for an environmental reason (`env -u KISO_DELEGATION_CONFIG_JSON …`).
- `packages/tui/tests/a7-dogfood-replay.test.ts` can flake under the parallel
  pool and passes in its own run.
