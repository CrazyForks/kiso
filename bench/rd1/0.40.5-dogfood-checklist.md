# 0.40.5 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.40.5 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.40.5
kiso --version        # 0.40.5
```

## A. A session knows which kiso it runs

1. A session opened BEFORE the install cannot say so — the notice is not in
   its code. Exit those and resume them (`kiso resume <id>`).
2. In a session opened on 0.40.5, `/status` ends with `version 0.40.5`.
3. The notice itself is proven by the end-to-end gate (the built CLI
   upgraded underneath a live session). You first meet it at the next
   upgrade: a session opened on 0.40.5 and still open when 0.40.6 is
   installed says, after its next turn, `✦ kiso 0.40.6 is installed — this
   session runs 0.40.5; exit and resume it (kiso resume <id>) to use it` —
   once.

## B. The README

1. Read `README.md` (or `README.zh.md`) on GitHub once, top to bottom.
   - **Expected:** it says what kiso is before anything else; the
     commands and keys you use daily are in the two tables; nothing you
     would look for is missing from docs.
