# 0.40.2 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both sessions go
into the record before 0.40.2 is APPROVED. This list is what the owner's
pass should look at: the surfaces this release changed.

Install the published build first:

```
npm install -g @vincemakes/kiso-code@0.40.2
kiso --version        # 0.40.2
```

## A. A long session no longer grows with every compaction (the P0)

1. Optional, before starting: add `"contextWindow": 1048576` to the `op`
   profiles in `~/.kiso/config.json`. Without it the row shows `ctx ?` and
   compaction assumes 200K; with it the row shows a real percentage.
2. Start kiso on the profile you use for long work and give it a task that
   runs for a while (many reads and edits).
   - With no stated window, stderr says once at start:
     `[kiso] context window unknown for <model> at this endpoint — compaction assumes 200K; set contextWindow on the profile to state it`.
3. Watch the transcript for `✦ compacted mid-run — the conversation before
   this point is a summary now · ctx now ~N% used`.
   - **Expected:** after each compaction the ctx figure DROPS, and a second
     compaction does not follow straight after the first.
   - **The old defect looked like:** a compaction notice on almost every
     round, and the ctx figure climbing anyway.
4. If a `✦ compaction discarded — the checkpoint did not shrink the context
   (~pre → ~post; it wrote ~n)` line appears, the new guard threw away a
   summary that would have grown the context. Note how often it appears.
5. Afterwards, from the kiso checkout, sizes only (never the summary text):
   ```
   node scripts/replay-projection.mjs ~/.kiso/projects/<project>/<session>.jsonl
   ```
   `projected.summaryMessages` must be 1 however many compactions ran.

## C. The poisoned session answers again

`~/.kiso/projects/-Users-vinve/2026-09-22T01-58-27-0027` — every request
there was a 400 ("tool_calls must be followed by tool messages").

- Resume it and send one line.
- **Expected:** no 400. The call that never ran (`call_02_…`) now reads
  "aborted before execution" in the transcript.

## D. esc in the middle of a batch no longer poisons a session

1. In bypass mode, ask for three slow shell commands in one go (for
   example three `sleep 5 && echo n`).
2. Press esc while the first one runs.
3. Send another message.
- **Expected:** it is answered. On 0.40.1 every later request was a 400.

## E. The status row names the model only

On a profile whose model id carries a vendor (`deepseek/deepseek-v4.1-flash`):
- **Expected:** the row shows `deepseek-v4.1-flash`. `/model` and `/status`
  still show the full id and the host.
