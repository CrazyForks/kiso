# DC-55 — a refused session switch kills the REPL and leaves a session nothing ever ran in

- **id:** DC-55
- **class:** REPL lifecycle / error propagation (startup-adjacent)
- **severity:** **P1.** A single `/resume <id>` (or a pick from the
  picker) can end the whole process: the refusal is thrown out of
  `chatLoop`, the message lands at the shell prompt as though kiso had
  crashed, and the session that WAS open is left behind as a sidecar with
  no log at all — announced once by its own banner, then empty, unopenable
  and invisible to `kiso sessions`.
- **agent:** kiso 0.40.0, reported from a real session (the owner, on
  their own machine, three times in twenty seconds).
- **found by:** the owner, with the terminal transcript and the three
  corpses on disk.
- **status:** **FIXED** in this round (0.40.x), red before green — and
  half of the defect is *structurally gone*: the binding refusal that
  triggered it no longer exists (the owner's ruling of 2026-09-21, this
  finding). The guard added here covers what the profile contract still
  refuses: an unreadable sidecar and an XP-era log without one.

## What the owner saw

```
vinve@MacBook-Pro uooki % /resume
zsh: no such file or directory: /resume
vinve@MacBook-Pro uooki % the recorded execution profile no longer matches this process:
- the recorded provider is deepseek but the current process serves custom
re-open with acceptDrift (the CLI's --accept-drift flag) to proceed …
vinve@MacBook-Pro uooki %
```

The message reads as a crash because it IS one, from the REPL's point of
view: the process exited between the banner and the first answer. The
`/resume` at the shell is the human's next move after a dead kiso — it is
not the gesture that caused it (that one was typed inside the TUI, or
picked from the picker).

## The three corpses

`~/.kiso/projects/<project>/` held three sessions created seconds apart,
each one the remains of a REPL that tried to switch to an older session:

| ghost session | project | sidecar written | ledger (`traces/`) |
|---|---|---|---|
| `2026-09-21T06-31-23-5b25` | uooki | 06:31:23.568Z | `header` + `run_end(-1)` |
| `2026-09-21T06-31-41-c6a4` | uooki | 06:31:41.774Z | `header` + `run_end(-1)` |
| `2026-09-21T06-32-46-0826` | reelfo | 06:32:46.528Z | `header` + `run_end(-1)` |

Each has `<id>.meta.json` (a revision 1 profile and a summary in state
`open`), a ledger with no request line, and **no `<id>.jsonl` and no
`<id>.lock`** — nothing was ever spoken in them. `listSessionSidecars`
skips a session with no log, so the id the banner announced cannot be
found again afterwards.

## The path

`apps/cli/src/index.ts`, `chatLoop` — the loop's top:

```ts
const session = await agent.session({ id, … });   // unguarded
```

`/resume <id>` and the picker both end `chat()` with a switch request, and
the loop re-enters on the new id. When `agent.session` refused the open
(the profile gate), the throw left `chatLoop`, left `main`, and the entry
catch printed it and exited 1 — after the *new* session had already been
created by the opening open. The session was real (its revision 1 landed,
its summary said `open`), and the human never typed into it.

## The fix, and the ruling behind it

1. **The ruling** (the owner's ruling of 2026-09-21, this finding): a
   recorded binding the process no longer serves is not a refusal at all —
   the CURRENT configuration wins, the change is recorded as the next
   revision, and the session says so in one line. That removes the
   trigger.
2. **The guard** (this finding): the open is wrapped. The ENTRY open still
   fails loudly — `kiso resume <id>` keeps its message and non-zero exit,
   because nothing is on screen to preserve. An IN-SESSION switch prints
   the message, switches **nothing**, and the session you were in stays
   open. A refused open writes nothing: the target's sidecar is untouched
   byte for byte.

## Red before green

- `packages/runtime/tests/xp1-binding-never-blocks.test.ts` +
  `xp1-profile.test.ts` + `profile-workspace-name.test.ts` — **red 4 /

- Pre-patch reproduction, hand-run: a faux session (recorded provider
  `null`) plus `--model co`, `/resume probe-old` → `exit=1`, the raw
  refusal on stderr, and a log-less `probe-new.meta.json` left behind.

## What this does NOT cover

The refusal is a line only where a session is already open. The two
integrity cases still end the *entry* (correctly — that is the entry's
error), and DC-57 (a line that arrives in the same read as a switch is
answered by the session being left) is a different mechanism, recorded and
unfixed.
