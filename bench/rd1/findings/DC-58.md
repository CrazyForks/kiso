# DC-58 — the /model picker could not be scrolled: nine profiles were reachable, the rest were not

- **id:** DC-58
- **class:** TUI / selection surface reachability
- **severity:** **P2.** Nothing crashes and nothing is lost — but on a config
  with more than nine profiles the picker's keyboard reaches the first nine
  and the rest can only be typed by name, which is the chore bare `/model`
  exists to remove. The owner has ~60 profiles; the reference the survey
  used scrolls its list.
- **agent:** kiso 0.40.0 (TUI2-R2 ④'s pick panel).
- **found by:** the owner, 2026-09-21 — "with `/model` I can only look at up
  to nine; the other implementation can open all of them".
- **status:** **FIXED** in this round, red before green.

## The mechanism

`PICK_MAX = 9` was documented as a *digit* bound ("the digits are the keys, so
the list the panel offers is bounded by the digits there are") and then used
as the list's bound in three places:

| place | line | what it did |
|---|---|---|
| the block's rows | `approval-panel.ts` | `slice(0, min(budget, PICK_MAX))` — the window was pinned to the TOP |
| the cursor | `panel-input.ts` (arrow) | `Math.min(options.length, PICK_MAX)` — ↑↓ stopped at row nine |
| the digits | `panel-input.ts` (digit) | the same bound, absolute indices |

So the nine were not "one screen of many": they were the whole reachable set,
and the block said so with `└ +N more — /model <name> takes any of them`.

## The fix

`pickWindow(cursor, count, size)` — one pure helper, edge-following and
clamped so the last screen is full — is now the single source for the window's
origin. The renderer draws `slice(first, first + size)`; the cursor walks the
whole list; a digit names the row ON SCREEN (`first + i`), so what the row
shows and what the key does cannot drift; and the range line replaces the old
sentence: `↕ A-B / N — ↑↓ scrolls`.

Two index bugs fell out of the change and the new gate caught both: the cursor
mark and the effort-axis lookup were comparing a position inside the window
against the absolute cursor, so after any scroll no row was marked at all.

## Evidence

- `packages/tui/tests/dc58-pick-viewport.test.ts` (new, 11 cases) — **RED 8 /
  green 11** on the pre-patch renderer; the whole tui + tui-cells pools are
  green (135 files, 1422 tests).
- The three cases that pin the contract: `pickWindow` edge-following and both
  clamps; the drawn rows and the range line at cursor 0 / 12 / 59 with 60
  options; and the keys (twelve ↓ reach the thirteenth option, `1` after a
  scroll picks the first VISIBLE row, a digit past the window is inert).
