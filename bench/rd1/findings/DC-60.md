# DC-60 — a session that never began leaves files behind, and shows in /resume

- **id:** DC-60
- **class:** persistence hygiene — files for a session with no durable event
- **severity:** **P3.** Nothing is lost or wrong, but the list grows with
  cards that say "no summary" and open onto nothing.
- **agent:** every kiso up to 0.40.2.
- **found by:** the owner, noticing ghost sessions in /resume (2026-09-22);
  the mechanism traced by the agent.
- **status:** **FIXED** in this round (the owner asked for it on
  2026-09-22; scope confirmed 2026-09-23).

## What leaves the files

A session id is minted at start-up, and three writes followed before the
person ever typed:

1. `agent.session()` wrote the sidecar's revision 1 at OPEN
   (`packages/runtime/src/agent.ts`, "a NEW session: revision 1 lands BEFORE
   any durable event").
2. `kiso chat` runs `session.resume()` at every start (the crash recovery).
   With nothing to recover, that run still initialised the request tracer
   — the trace file's `header` — and closed it with `run_end`.
3. The same run's end wrote the sidecar's summary row (`state: open`,
   `turns: 0`).

Close kiso there, or let a delegated child fail before its first turn, and
the session is a sidecar plus a trace with no log.

## The owner's disk (read-only, 2026-09-23)

56 such sessions: 28 in the project folders (every one the same shape —
sidecar revision 1 with a summary row, trace `header`+`run_end`, no log,
no lock; 12 of them delegated children) and 28 in the legacy
`~/.kiso/sessions` folder. None held by a live process.

## The fix

- A NEW session writes nothing at open. Its revision 1 — with the
  workspace it opened in — lands with its first durable event, still
  BEFORE it (`session.persist`): a log line never exists without its
  profile, so XP-1's fail-closed rules are unchanged. A model switch before
  that event stays in memory and is what revision 1 records.
- A resume with no durable event returns before the tracer starts: no
  header, no `run_end`, no summary row. The summary row is also skipped for
  an empty log wherever it is written.
- `kiso sessions --prune-empty` lists the sessions that never began;
  `--yes` MOVES them to the Trash (one new folder, each project folder's
  name kept), never deletes. A session whose lock names a live process is
  skipped and counted.

## Gates

- red: open + the start-up resume left `s.meta.json` and `traces/s.jsonl`;
  a model switch before the first event wrote `s.meta.json` / green:
  nothing on disk; the first turn brings revision 1 with the opening
  workspace and the switched model.
- declared re-pins: XP-1's "a NEW session writes revision 1 before any
  durable event" and the two setModelBinding revision tests now start with
  a first turn — the write moved from open to the first event.
- `--prune-empty` scan and move: mkdtemp folders only (a real session, two
  empty shapes, one in use).
