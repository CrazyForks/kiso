## What is in it

The products' adoption requests (their leader session filed 13; six are
here, the dispositions of the rest are in the round's review document,
kiso-doc `review-0420-changes-for-the-13-requests-2026-09-25.md`):

| PR | what changed |
|---|---|
| #139 | an extension's `systemPrompt.append` may be a FUNCTION; `AgentDefinition.toolTable: "off"` withholds the generated "Tool use:" block (the tool schemas still ride the request) |
| #141 | **kernel:** the reserved tag `END_TURN` on a tool result ends the turn — the loop writes `completed` instead of asking the model again; `ToolContext.callId` / `executionId`. 4 core files, 33 lines; the frozen Event union unchanged; the size gate 2,199 / 2,200 |
| #142 | the append is evaluated per model request, not per run; the HTTP transport's `prepareInput` may answer the request itself (`{ handled: true }`) |
| #143 | **the review's two fixes:** END_TURN decided at the HEAD of every turn, scanning the log back to the most recent stop / user_input / terminal — a cold resume after a crash between the tagged result and the next request now completes with zero requests, as the fresh path does (both crash windows were red on the tail-only check); the dynamic append evaluated exactly ONCE per provider attempt by `promptPerAttempt`, the outermost adapter layer — the same evaluation is what the model is sent and what the trace records (the getters had run the function four times per request) |

Rulings from the review, adopted: END_TURN is a kernel semantic; the tag
is authoritative regardless of `isError`; no terminal reason in 0.42.0;
a retry is a new attempt.
