# 0.44.0 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.44.0 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.44.0
kiso --version        # 0.44.0
```

## A. A normal session

A session on a real task behaves as 0.43.0 did. The banner still reads
`[3 extensions: built-in: mcp, skills, subagent]`; `/status` ends with
`version 0.44.0`.

## B. No task surfaces

- A multi-step task draws no checklist, and after the last step there
  is no "verify?" offer.

## C. An old session that used the task extension (only if you have one)

- `/resume` a session recorded while the task extension was loaded
  (built in through 0.2.2, opt-in after): its `task_set` calls show as
  ordinary tool rows, and the session continues normally.

## D. What would be a finding

- Any behaviour that differs from 0.43.0 on the same task, other than
  the absent checklist and verify offer.
