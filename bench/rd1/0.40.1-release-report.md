## Bench: NOT run this round, and why (BM-1 rule 3)

BM-1's causal-relevance gating says the blocker set follows the change surface,
and for a **UI/renderer round the live paired bench is informational**, not a
blocker. This round is exactly that plus a contract change:

| surface | tier | blocker |
|---|---|---|
| #96 (ask panel does not take the mouse) | UI/renderer | PTY/visual/width gates |
| #97 (picker rows, provider display, switch handoff) | UI + CLI input routing | PTY gates + the CLI behaviour gates |
| #95 (binding identity, resume admission) | contract | runtime profile/binding tests + the CLI gates |

Nothing here touches prompt construction, tool schemas, compaction thresholds or
context assembly — the surfaces whose tier makes the paired bench block. So the
$5-18 a T3+T5 paired round would spend buys the anomaly-detector line, not a
verdict, and it was left unspent by the owner's decision. (Measured basis, for
the record: the archived rounds are 603 requests for the T3 shape, 757 for T5,
2,131 for T6, at ~11.7K input tokens per request.)
